# Specification 000: System Architecture & Bootstrap

## 1. System Invariants
- **Host**: Hostinger VPS (`srv1702496`), managed under user `deploy`.
- **Domain**: `mathquest.mainuddintalukdar.cloud`.
- **Edge Routing**: Existing Caddy reverse proxy container (`stack-caddy-1`) listening on ports 80/443, connected to Docker network `stack`.
- **Zero Exposed Host Ports**: Neither `mathquest-web` nor `mathquest-scoring` publish any host ports.
- **Microservice Isolation**: `mathquest-scoring` is connected exclusively to private Docker network `mathquest-internal`. It runs on port `8005` (preventing any collision with `tradiepulse-ai-agent:8000` on the host).
- **Stateless Scoring**: `mathquest-scoring` has no direct database or internet connection; it receives sanitized attempt summaries and returns explainable scores.
- **Client Answer Masking**: Question answer keys and solutions are NEVER served to the browser. Answer verification occurs strictly server-side in Next.js route handlers.
- **Child Privacy Guarantee**: No child emails, full dates of birth, school names, locations, or free-form chat are stored.

## 3. Data Model & Entity Relations
- `profiles`: Linked 1:1 with `auth.users`. Contains guardian contact info and account preferences.
- `children`: Child profiles belonging to a guardian (`guardian_id -> profiles.id`). Fields: `nickname`, `age_band`.
- `topics`: Primary math subject areas (`number_sense`, `addition_subtraction`, `multiplication_division`, `fractions`).
- `lessons`: Sequential lessons within topics with difficulty levels and learning objectives.
- `questions`: Question prompts, layout types, structured choices, and progressive hints.
- `question_solutions`: Private solutions table accessible only to `service_role` and security-definer validation functions.
- `learning_sessions`: Active learning instances with idempotency keys.
- `question_attempts`: Server-validated records of child attempts, hint usage, durations, and correctness.
- `mastery_scores`: Versioned composite mastery calculations generated by the scoring service.
- `practice_recommendations`: Recommended next topic/lesson based on prerequisite rules and mastery levels.

## 4. Scoring Microservice Algorithm (`rule_v1.0.0`)
1. **Weights**:
   - Accuracy: 70%
   - Attempt Efficiency: 20%
   - Pace / Speed: 10%
2. **Pace Handling**:
   - Durations under 3 seconds are clamped to 3s (flagged as possible rapid guessing).
   - Durations over 60 seconds are clamped to 60s (speed is treated as a weak signal).
3. **Confidence & Sample Size**:
   - Fewer than 3 attempts: returns `confidence: 0.0`, score marked as `insufficient_data`.
   - 3–9 attempts: `confidence: 0.5` (provisional).
   - 10+ attempts: `confidence: 1.0` (established).
4. **Recommendation Logic**:
   - Evaluates prerequisite chains (e.g., addition must be >= 70 before multi-digit addition; multiplication arrays before fractions).
   - Selects the lowest confidence-adjusted score topic that meets all prerequisites.
